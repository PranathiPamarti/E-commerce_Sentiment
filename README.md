# E-Commerce Review Intelligence & Customer Analytics

A Streamlit and Plotly project for exploring product reviews, rating-derived text sentiment, rule-based issue candidates, and reviewer activity patterns.

## Run the application

From the repository root in PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.prepare_review_intelligence
python -m src.train_review_sentiment
python -m streamlit run app/app.py
```

The preparation step downloads the Amazon Reviews 2023 **All_Beauty** category and writes a deterministic sample of up to 400,000 valid reviews to local Parquet. The current prepared sample has 399,596 reviews, 87,139 products, and 373,031 reviewers. Raw and processed review data and model artifacts are ignored by Git and should remain local.

## What is actually trained?

There are **two separate saved text-sentiment pipelines**:

1. **Main review-intelligence model:** three-class TF-IDF word unigrams/bigrams and balanced `SGDClassifier(loss="log_loss")`. It uses star ratings as weak labels: 1–2 negative, 3 neutral, 4–5 positive. The 399,596-row sample has 15,586 normalized exact-text duplicate rows removed before a chronological 60% train / 10% tuning / 10% out-of-time validation / 20% held-out test split. Two regularization settings are compared; the selected model is refit on the first 80%. Each training run makes three `.fit()` calls and saves one final model. The current held-out test has 76,802 reviews, 85.12% accuracy, and 0.6997 macro-F1, versus 64.70% accuracy and 0.2619 macro-F1 for the majority-class baseline. Neutral-class F1 is 0.3584. These metrics measure agreement with rating-derived labels, **not human sentiment truth**.
2. **Synthetic-demo model:** binary TF-IDF sentiment classifier for the separate synthetic app screens. It compares logistic regression and Multinomial Naive Bayes on 990 deduplicated UCI Amazon cell-phone review sentences, then saves one final pipeline. The latest 198-row test result is 81.82% accuracy and 0.818 macro-F1. This small, separate experiment is not the main All_Beauty model.

The main training command generates 115,203 out-of-time predictions across 37,068 products for dashboard sentiment. The dashboard reads saved predictions and metrics; opening it does not retrain the model. The interactive **Sentiment model** page also lets you try the saved pipeline on a review.

The recommendation screen is a **synthetic prototype**, not a trained recommender: its user/product latent factors are generated by the simulator. The rule-based issue taxonomy is also not machine-learned.

## Dashboard pages

- **Project overview:** project scope, headline results, model count, and measured limitations.
- **Dataset and data quality:** sample size, product/reviewer counts, data checks, ratings, review length, and time coverage.
- **Sentiment model:** labels, features, chronological split, model selection, per-class results, confusion matrix, and prediction demo.
- **Issues and products:** candidate tag frequencies/rates, emerging signals, product comparisons, and review drill-down.
- **Reviewer signals:** activity, reused text, and out-of-time negative-share patterns. These are investigation signals, not evidence of manipulation.
- **Human issue-tag audit:** blinded annotation workflow, weighted population estimates, uncertainty, and agreement for double-coded reviews.
- **Synthetic demo:** the older product insights and recommendation screens, clearly separated from the public review analysis.

The UI uses a neutral light theme. The primary workflow is documented in the [interview study guide](./INTERVIEW_GUIDE.md) and demonstrated in the executed [review-intelligence notebook](./notebooks/1_data_cleaning_eda.ipynb).

## Issue-tag validation

The 32 regex rules produce candidate issue tags from review text; they are not validated defect labels. A stratified random audit oversamples candidate-tagged reviews and uses inclusion weights to estimate population precision and recall. The current 400-review sample has **0 completed human labels**, so issue-tag precision has not yet been measured and **91% precision is not a supported claim**. Complete the primary annotations in the app before reporting audit results.

## Reproducibility

The project code is in `src/`; the app is in `app/`; focused unit tests are in `tests/`. Run tests with:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The public source is the [Amazon Reviews 2023 dataset](https://amazon-reviews-2023.github.io/), described by Hou et al., [“Bridging Language and Items for Retrieval and Recommendation”](https://arxiv.org/abs/2403.03952). Review content and saved artifacts are excluded from Git; follow the dataset's terms when using or redistributing it.
